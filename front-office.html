Front Office — Fantasy Football Platform
A full-stack fantasy football platform I'm engineering with Claude Code as the build agent. I wrote the product spec and own the architecture and security decisions; the agent implements each phase against a written design doc, and a phase isn't done until tests, lint, type-checks and the build all pass.
stack: Claude Code · TypeScript · Node.js · Fastify · React · PostgreSQL · Drizzle ORM · Zod · Vitest · Docker
ben@raleigh:~/projects/ai/front-office$ cat workflow.md
  • Spec-driven AI development. One master product spec is written as a directive to the agent: scope, phases, constraints, and what not to build yet.
  • Design before code. Every phase starts as a design doc, gets reviewed, then gets built. Where the build deviates from the plan, the doc records why.
  • Architecture Decision Records. Datastore, audit log, authentication, data model and feed design are each an ADR with the options weighed and the trade-offs accepted.
  • Verification gates. 100+ automated unit and integration tests run against a real PostgreSQL database, plus lint, strict type-checking and a full build on every phase.
  • Agent guardrails. An early test run truncated the development database. Tests are now hard-pinned to an isolated database, so neither I nor the agent can wipe real data by running them.
ben@raleigh:~/projects/ai/front-office$ cat docs/adr/0003-self-hosted-session-auth.md
  • Self-hosted auth, no third-party identity SaaS. Chosen deliberately in an ADR: no external dependency, and the security correctness is ours to test.
  • Argon2id password hashing, verified by tests that check the stored value is an Argon2id hash and never the plaintext.
  • Opaque 256-bit session tokens. The browser holds the token in an httpOnly, SameSite=Lax cookie (Secure in production); the server stores only a SHA-256 hash, so a database leak doesn't hand out live sessions.
  • Server-side expiry checked on every request, and request payloads validated against Zod schemas at the API boundary.
  • Auditable data. NFL stat corrections are versioned with provenance instead of overwritten, so every score change leaves an audit trail.
